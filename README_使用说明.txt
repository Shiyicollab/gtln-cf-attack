GTLN 连分数密钥恢复：代码与实验使用说明

一、这份程序做什么

攻击输入是公钥整数 t_1,...,t_n，以及 b、beta、Cp、Cg。
它寻找区间 [2^b,2^(b+beta)) 中两两互素的私钥整数，以及对应的模数 g 和偏移 u。
候选整数可以是合数；攻击程序不做素性判定、不做因数分解，也不接收真实私钥或明文重量 t。
Cp、Cg 是显式搜索上界，程序不会自行扩大它们。

实验只生成原始 GTLN 论文推荐的 24 组素数型私钥，每组 100 把。
密钥生成阶段需要素性判定，攻击阶段不需要。实验没有生成合数私钥再实施恢复。

二、文件分别负责什么

cf_attack.py          独立的公钥攻击：连分数、候选整数、互素性、模数和公开方程检查。
key_generation.py     24 组推荐参数、可复现随机数流、素数型密钥生成。
benchmark.py          批量实验；攻击结束后才读取真实私钥作正确性核对。
attack_public.py      只读取一个公钥 JSON 并输出候选私钥。
RESULTS.txt           本次运行的总结果与逐组时间。
RESULT_COLUMNS.txt    原始记录和汇总表的字段解释。
results/              2400 次逐次记录、24 组汇总、运行环境及 24 个示例公钥。
SHA256SUMS.txt         交付文件的 SHA-256 校验值。

全部程序只依赖 Python 标准库，无需安装 SageMath、格约化库或其他第三方包。
推荐用 Python 3.12 复现；代码要求 Python 3.10 或更高版本。

三、算法实际上按什么顺序恢复

1. 找到最小、最大的公钥项，得到两个端点和差 D。检查 zD > 4Q^2+1，
   其中 z=2^b、P=2^(b+beta)、Q=2P^3。检查失败就返回空集合。
2. 对每个非端点坐标计算 (t_i-t_l)/D 的有理逼近，得到约分后的 N_i/M_i，
   并用整数运算检验误差条件。计算 gcd(M_i-N_i) 和 gcd(N_i)。
3. 在区间和 Cp 允许的范围内试除这两个 gcd。只保留能整除、商位于 [z,P)
   的候选整数，不要求商为素数。枚举两个端点候选的组合；两端必须互素。
4. 用论文中的 U_i/V_i 公式恢复其余坐标，检查正分母、整除和范围。
   对完整整数向量作两两互素检查：维护前面整数的乘积 T，每个新整数 p
   必须满足 gcd(p,T)=1，然后更新 T。不同但不互素的整数不能通过此检查。
5. 对固定第一个坐标的 n-1 个表达式求 gcd，得到 g0。枚举
   1 <= c <= min(Cg, floor(g0/(max(t_i)+1))) 中整除 g0 的 c，设置 g=g0/c。
   用一个模逆恢复 u，再检查全部公开方程。所有通过的候选都返回。

输出可能为空、恰有一个候选或有多个候选。程序不会在找到第一个候选时停止，
也不把“有一个匹配公钥的候选”自动等同于“找到了原始私钥”。
原始私钥包含在输出中的保证，需要比值分离条件成立且三个真实余因子不超过上界。

四、怎样运行完整实验

将压缩包解压，进入包含 benchmark.py 的文件夹，在终端运行一行命令：

python benchmark.py --trials 100 --Cp 2 --Cg 2 --seed 20261012 --out results_rerun

这会依次运行全部 24 组参数，每组 100 把密钥。results_rerun 必须是一个尚未
包含实验记录的新目录，防止覆盖数据。若系统使用 py 命令，可把 python 换成 py -3。

快速运行三组参数、每组两把密钥：

python benchmark.py --sets 1,17,24 --trials 2 --Cp 2 --Cg 2 --seed 20261012 --out quick_run

--sets 是 1 至 24 的组号，用英文逗号连接；all 表示全部。
--trials 是每组生成密钥的次数。--seed 控制样本，--Cp 和 --Cg 控制固定搜索上界。
同一 Python 版本、相同种子和参数可复现公钥样本及数学结果；计时取决于机器和负载。

五、怎样只攻击一个公钥

无需密钥生成，也不需要已知答案：

python attack_public.py results/public_set_01.json --Cp 2 --Cg 2 --out recovered.json

JSON 输入格式包含三个字段：
  b：整数；beta：整数；public：公钥整数列表。
公钥的大整数使用十进制字符串保存，避免其他软件读取 JSON 时损失精度。
输出文件包含状态、计时、搜索计数及全部候选。候选中的 p、g、u 同样保存为字符串。

六、怎样理解本次实验

密钥生成：随机选取区间内整数后取严格大于它的下一素数，越界或重复就重新抽取；
g 按原论文位长规则选取并与所有私钥整数互素；u 按允许范围选取。
素性判定只服务于这个生成过程，采用前 12 个素数基的确定性有效区间。
生成器支持本次全部参数（最大 b+beta=71），并明确限制 b+beta<=78；
公钥攻击没有这一素性判定大小限制。

计时包括整个攻击过程：公钥检查、连分数、候选枚举、互素检查、模数搜索及公开方程验证。
计时不包括密钥生成、真实答案核对或文件读写。程序在一个进程中顺序运行。
攻击停止计时后，评价程序检查原始私钥是否在返回集合内、是否唯一，还用真实私钥
核对中间比值和三个余因子。评价结果不会反馈给攻击搜索。

实验数据能说明本次推荐参数和生成方式下的表现，不能证明任意合数型私钥的余因子
都落入上界 2，也不能靠 2400 个样本验证 2^(-80) 级的概率；该概率来自论文中的随机模型。
