GTLN Continued-Fraction Key-Recovery Experiment Results

Experiment date: 2026-10-12
Attack inputs: public key, b, beta, Cp, and Cg; candidate private integers
are required to be pairwise coprime, but need not be prime.
Key generation: the 24 recommended parameter sets from the original paper,
with every private coordinate p_i prime.
Trials: 100 keys per set, 2,400 keys in total. Cp=Cg=2; seed 20261012.
Environment: Intel(R) Core(TM) i7-14700; Windows 11; CPython 3.12.14.
Timing: sequential execution in one process; includes the complete attack
and excludes key generation, ground-truth evaluation, and file I/O.

Overall results
  Unique candidate equal to the original private key: 2400/2400
  Original private key included in the candidate set: 2400/2400
  No candidates: 0; multiple candidates: 0; incorrect unique candidates: 0
  Exact ratio recovery: 2400/2400 trials, covering 392700 ratios
  Mean attack time: 14.283 ms
  Median attack time: 8.611 ms
  95th-percentile attack time: 34.800 ms
  Maximum attack time: 42.590 ms
  Range of per-set mean attack times: 4.672--40.814 ms

Cofactors and search
  Every sample had f_lo=f_hi=c=1.
  Each endpoint had exactly one candidate integer; one endpoint pair was
  examined in each trial.
  Each trial produced one complete vector of pairwise coprime integers.
  Every trial had floor(g0/(max(t_i)+1))=1, so only c=1 was enumerated.
  Each trial performed one complete verification of the public equations.
  The total number of endpoint-cofactor trials ranged from 2 to 4 per key;
  each cofactor was tried before divisibility and interval filtering.
  In these samples, all rejection counts for non-coprime endpoints, failed
  reconstruction, and non-coprime complete vectors were zero.

These statistics concern prime-based key generation. For general pairwise
coprime private integers, inclusion of the original key is conditional on
the separation condition and on all three true cofactors lying within the
specified search caps. The very small failure-probability estimate for caps
of 2 comes from the heuristic random-gcd model; the finite sample above
cannot establish that estimate on its own.
